# AXES 5070 — doctrine profiler multi-axes pour Qwen3.5/3.6-35B-A3B (2026-09-21)

Source : croisement littérature 2024–2026 (MoE-Infinity, Oracle-MoE ICML'25, fMoE,
ExpertFlow DAC'26, CoX-MoE, SSD-LLaMA) + implémentations communauté (wackMall,
Leloch, Lidenburg, MaxDam, blobpager, moe-expert-cache) + principes D2
(coût/gain/ROI par axe, critical path, marginal, Pareto).
**Règle racine** : aucune métrique ni optimisation sans coût matériel + gain
net mesurable (`NET_HARDWARE_GAIN = critical_path_saved − compute_added −
DMA_added − sync_added − memory_pressure − overhead`).

## 1. Correction majeure au plan §9 (leçon communauté #24528)

Le budget d'experts n'est PAS `VRAM − KV` :

```
budget_experts = free_vram − permanent − KV − worst_case_compute_buffer − rail
```

Sur 5070 8 Go (hypothèses ASSUMED, à valider par run llama.cpp réel) :
permanent ≈ 1.5 GiB (emb+LM head vocab 248k ≈ 0.5, backbone 30 GDN + 10 attn
≈ 0.9, 40 routers + 40 shared experts ≈ 0.15), compute buffer ≈ 0.5, rail ≈ 0.3
→ **résidence réelle ≈ 101/256 NVFP4 @8k** (et non 143 = plafond poids-seuls),
**53/256 @64k**. Le 143 reste la borne supérieure théorique.

**Runs `SORTIE_5070_AXES.txt` (3 scénarios)** : NVFP4@8k → 101/256, hit 0.45,
miss→transfert GPU gagne (0.27 ms pinned vs 0.49 ms CPU) ; Q4@8k uniforme →
51/256, hit 0.20, **miss→compute CPU gagne** (0.72 vs 0.78 ms) — la décision
miss s'inverse avec le format ; @64k → 53/256, prefetch masque 100 % du DMA
visible (t_compute 9.1 ms >> t_h2d 0.37 ms). Ledger : prefetch +8 t/s sur
Q4 uniforme (le pire monde), +1.8 t/s sur NVFP4 skewed. Marginal : +1 GiB
cache = +21 experts = +0.083 hit (NVFP4) — rendement décroissant visible.

## 2. Seconde correction : plus de cache ≠ plus rapide

Mesures 2080 Ti (35B, communauté) : cache 16 experts PIRE que CPU-only,
pic à 160, régression à 196. Modélisé ici par sweep avec budget contraignant
+ hit skew (2 mondes : localité forte → cache gagne ; routing quasi uniforme
→ LRU inutile, cf. débat O_DIRECT/LRU vs page cache).

## 4. Modèle d'experts (3 tiers, non copié d'un seul projet)

```
HOT  → VRAM cache      (budget = formule §1, hit skew paramétrable)
WARM → pinned RAM      (DMA direct, pas de bounce buffer)
COLD → mmap/SSD        (dernier niveau ; page cache noyau parfois meilleur
                        qu'un cache userspace mal fait)
MISS → décision : transfert GPU vs compute CPU (coût explicite)
Pipeline : router(N) → prefetch(N+1) sur stream séparé (MaxDam async)
```
