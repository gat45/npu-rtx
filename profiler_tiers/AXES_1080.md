# AXES_1080 — modèle de profilage complet GTX 1080 (sm_61) — 2026-09-21

Transposition des 18 domaines profiler-v3 aux contraintes matérielles RÉELLES
de la 1080. Règle : chaque axe a un STATUT (MEASURED / MODEL / ASSUMED /
UNKNOWN / N-A) et un INSTRUMENT. Cible d'usage : profiler le 35B-A3B
(recette Genesis mesurée) layer × expert × quant.

## Contraintes matérielles qui commandent tout

| Contrainte | Valeur | Conséquence de modélisation |
|---|---|---|
| GPU | GTX 1080 8 GB, Pascal **sm_61** | tensor cores ABSENTS → FP8/FP4 = stockage + déquant émulée uniquement |
| BW mémoire GPU | 205 GB/s effectif (64 % de 320 théo) | decode **BW-bound** : t_gpu = octets lus / BW |
| VRAM | 8 GB | budget experts = free − permanent − KV − compute_buffer − rail |
| PCIe | gen3 ×16 = **15.75 GB/s** | décision miss : H2D (15.75) vs compute CPU (~50 GB/s DDR) |
| NPU | **ABSENT** | Voie A/XDNA2 inactive — tous les axes NPU/XRT/DMA = N-A |
| RAM hôte | 32 GiB (14.6 libres) | pool experts > RAM → COLD/SSD, paging |

Le CPU (dispatch, gaps) et le PCIe restent des axes ; XRT, DMA NPU, tuiles
AIE, sync firmware disparaissent (N-A).

## Les axes (18 domaines → 13 actifs sur 1080)

### 1. TIMING [MODEL]
Variables : `wall_time`, `busy_time`, `critical_path_time`, `overlapped_time`,
`kernel_duration`, `layer_duration`, `token_duration`.
Instrument : CUDA events + `critical_path_5070.py` (MAX des jambes, jamais la somme).
Statut : MODEL valide (BW-bound simple). **FP8** : t_gpu croît avec les octets
→ FP8 (8.5 bpw) lit 1.55× les octets de Q5_K → *ralentit* le decode BW-bound.

### 2. CPU INSTRUMENTATION [MODEL]
Variables : `cpu.dispatch.submit/build/wait/poll`, `cpu.memory.*`, `cpu.sync`,
`measurement_intrusion` (baseline vs instrumented).
Instrument : compteur de segments T_token côté hôte.
Statut : MODEL — intrusion mesurable par run apparié.

### 3. PCIe / TRANSFERTS [MEASURED-datasheet + UNKNOWN]
Variables : `pcie_gbs=15.75` (gen3×16), `h2d_pageable` ASSUMED,
`h2d_pinned` **UNKNOWN**, `h2d_async`, taille utile par expert (1.57–3.34 MB).
Instrument : `microbench_h2d.py` (à lancer sur la 1080 — il y est, contrairement à la 5070).
Statut : le seul axe où la 1080 est *mieux* instrumentable que la cible.
Ancre qui compte : GB/s à 1–4 MiB (taille expert), pas le pic 256 MiB.

### 4. MÉMOIRE GPU [MEASURED]
Variables : `vram_used/free`, `weights/activations/KV/workspace/cache`,
`resident/mapped/allocated/touched`.
Instrument : nvidia-smi + budget du profileur (`profile_apex_matrix.py`).
Statut : budget MEASURED (header) sauf compute_buffer/rail ASSUMED (0.5/0.3 GiB).

### 5. KV / STATE [MEASURED-header + MODEL]
Variables : `kv_bytes = ctx × 40 × 2×2×256 × 2` (f16 ; head_count_kv=2, kv_len=256
lus du header), `state GDN` (borne basse, non modélisée finement).
Kinds dispo mesurés (build cu61) : f16 / q8_0 / **turbo4** ; **K=turbo3 INTERDIT**
(bug upstream garbage CPU+CUDA, bisect complet archivé).
**FP8 KV : N-A** — pas de kernel FP8 KV dans le fork sm_61.

### 6. PREFILL vs DECODE [MODEL]
Variables : deux modèles distincts (`PROFILE_PREFILL` compute-bound,
`PROFILE_DECODE` BW-bound), batch, context.
Statut : MODEL — le decode seul est profilé finement ici.

### 7. CONTEXT [MEASURED(borne)]
Variables : `kv_growth`, `cache_pressure`, `expert_distribution_shift`.
Statut : KV linéaire MEASURED ; shift routing avec contexte = UNKNOWN (trace 35B requise).

### 8. SCHEDULER [MODEL]
Variables : `dependency_graph`, `ready/scheduled/start/finish`, `critical_path`,
`serialization` — ici : overlap H2D (stream copy) vs compute.
Statut : MODEL (S0 série / S1 prefetch) — l'overlap récupère 6→28 % selon monde.

### 9. CONTENTION [N-A partiel]
Variables : `pcie_contention` (seul bus partagé), `ddr_contention` hôte,
`temperature/frequency/throttling` GPU.
Instrument : nvidia-smi (clocks, throttling),RW Everything pour PCIe.
CPU/NPU/GPU contention croisée : N-A (pas de co-processeur).

### 10. PROVENANCE [MEASURED-obligatoire]
Variables : `model_hash`, `gguf_hash`, `quantization`, `driver`, `cuda_version`,
`kernel_hash`, `git_commit`, `OS`, `hardware`.
Statut : écrit automatiquement dans chaque SORTIE_*.txt (microbench, profiler).

### 11. REPRODUCTIBILITÉ [MODEL]
Variables : `run_id`, `config_hash`, `baseline/candidate/delta/confidence`.
Statut : pattern CAN230921 repris — traces + manifestes commités.

### 12. MoE — EXPERTS [MEASURED ★ axe central]
Variables : `expert_id`, `layer_id`, `top_k=8`, `expert_bytes` (1.57–3.34 MB
selon quant), `expert_offset` (fichier réel), `expert_location`
(VRAM/WARM-pinned/COLD-SSD), `hit`, `miss`, `evicted`, `reuse_distance`,
`prefetch_accuracy`, `pool GiB par couche`.
Instrument : `profile_apex_matrix.py --per-layer/--layer N` (offsets réels du GGUF)
+ **hook routing** `GGML_ROUTING_TRACE` (patch archivé).
Findings mesurés (Marco-8B, famille qwen3moe) : **skew 0.305**, overlap
inter-tokens **2.5 %** → hot-set STATIQUE top-N par couche, LRU dynamique inutile.

### 13. QUANTIFICATION [MEASURED(header) + MODEL(requant)]
Variables : `storage_precision` (Q4_0 4.5 / Q4_K 4.5 / Q5_K 5.5 / Q6_K 6.5625 /
Q8_0 8.5 / **FP8 8.5** / turbo4 4.0 bpw), `dequant_cost` (émulée sm_61),
`accuracy_delta` (**PPL : à mesurer, jamais modélisé**).
Instrument : `--quant` (scale bpw exact) ; requant réel via llama-quantize
(à faire quand disque libéré) ; PPL par `llama-perplexity`.
Décision miss (MODEL, cpu_bw ASSUMED 50 GB/s) :
`t_h2d = miss_bytes/15.75e9` vs `t_cpu = miss_bytes/50e9` → compute CPU gagne
à toutes les quants ≥ turbo4 sur cette machine.

### 14–18. N-A sur 1080
DMA NPU, mémoire XDNA2 (DDR/L2/L1), tuiles/colonnes AIE, fusion kernels NPU,
XRT dispatch/BO/gaps — réactivables uniquement sur la cible XDNA2 (5070 side).

## FP8 — verdict axe par axe (35B Genesis, @8k, skew 0.305)

| Axe | FP8 (8.5 bpw) vs origine Q5_K-majoritaire (5.5–6.56) |
|---|---|
| Pool experts | **32.67 GiB** vs 22.87 (+43 %) |
| Résidence VRAM | 30/256 vs 44/256 |
| Hit (skew mesuré) | 0.52 vs 0.58 |
| t_gpu (BW-bound) | **+55 % d'octets lus** → plus lent |
| Decode 1080 | **93.7 t/s** vs 94.7 |
| PPL attendu | ~égal Q8_0 (marginal vs Q6_K) — à mesurer, pas à promettre |
| Tensor cores FP8 | **ABSENTS** (sm_61) — aucun gain compute |
| Verdict | **NON pour le decode 1080.** Usage légitime : référence PPL, future machine Hopper+/5070 compute |

Matrice complète (turbo4 95.4 > Q4_0 95.2 > Q5_K 94.9 > origine 94.7 >
Q6_K 94.4 > Q8_0 = FP8 93.7) : `SORTIE_1080_LAYERS_QUANTS.txt`.
